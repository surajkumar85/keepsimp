# This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` (resolved from this file's directory; in monorepos the `next` package may not be visible from the repo root) before writing any code. Heed deprecation notices.

This block is written and re-added by `next dev` — verify at `node_modules/next/dist/server/lib/generate-agent-files.js`. Removing it from a diff only re-creates the uncommitted change; committing it with your work keeps the tree clean.

## KeepSimp project rules

Read `docs/design-system.md`, `design-system/tokens.json`, and `docs/phase-one.md` before implementing product UI. The design reference is the persistent authority for future phases.

- Use Next.js App Router, TypeScript strict mode, npm, and the committed lockfile. The app exports static files; browser file processing must stay local. Do not introduce uploads, accounts, paid tools, or server processing without a user request.
- Preserve the requested shadcn preset `b2zSMmeGTw`: Base Nova, Base UI primitives, Tabler icons, Inter body, Outfit headings, Geist Mono code, and a teal brand. Do not substitute Radix or Lucide APIs from memory.
- Use sidebar-01's single panel with grouped navigation. The user rejected the double-sidebar layout: do not reintroduce nested sidebars or a second icon rail. Desktop width is 224px; mobile uses one 256px sheet with the same categories and keyboard access.
- Keep marketing routes (`/`, `/blog/`, `/privacy/`) separate from the compact workspace at `/dashboard/`. Marketing uses documented display typography and the warm surface token; dashboard controls and cards retain compact dimensions.
- Marketing links use `prefetch={false}` to avoid downloading tool bundles before intent and Safari errors when background route requests are interrupted. Preserve client navigation and use responsive static image sources for the exported site.
- Use the confirmed canonical origin `https://keepsimp.vercel.app`, overridable through `NEXT_PUBLIC_SITE_URL`. Include only public pages and completed tool routes in the sitemap. Vercel previews must remain noindex. Keep metadata, visible content, JSON-LD and tool availability consistent.
- Each kind of tool has a colour token (`category-video`, `-audio`, `-image`, `-document`, `-developer`) and each tool an icon of its own in `components/tool-icon.tsx`; give a new tool both. Category colours are for icons, category labels and card hover only, never for text on a tinted fill, buttons or states. Search lives once, in the header (`components/tool-search.tsx`, ⌘K / Ctrl+K); do not add a second search field to the dashboard.
- The articles at `/blog/` are called the blog, never the journal. Every tool that is ready has at least one article (`lib/blog.ts`, `lib/tool-blog.ts`, `lib/json-blog.ts`), and `lib/blog.test.ts` checks that, along with every link inside an article. An article has a heading in the site's voice (`title`), the question people type as its page title (`searchTitle`), and its topics (`keywords`). Write them in plain words, say only what the tools really do, and add a card to `scripts/social-images.mjs` for each new one.
- Reuse `components/ui`. Product screens use semantic tokens and named radius utilities. No arbitrary radii, hardcoded colors, copied Airbnb marks, or proprietary Cereal fonts.
- Reuse the outlined KeepSimp logo assets in `public/brand/` and the matching favicon. Preserve their proportions and geometry; use the light-wordmark variant on dark surfaces. Brand export colors are documented in `docs/design-system.md`.
- Edit `design-system/tokens.json`, then run `npm run design:generate`. Never hand-edit `app/design-tokens.css`. Update the reference and relevant browser assertions when intentionally changing the system.
- Use the compact density: 36px desktop controls and navigation rows, at least 44px on mobile. Label fields, keep focus visible, support reduced motion and both themes, and use honest loading/error/empty states. Planned tools must not appear functional.
- Put pure tool logic in `lib/` or its tool module, with meaningful unit tests covering edge cases. Browser tests should verify real journeys and actual outputs when engines arrive; do not substitute mocked processing for end-to-end validation.
- Before changing color workflows, read `docs/color-utility.md`. Preserve wide-gamut source values, explicit sRGB fallback labels, alpha-aware contrast, bounded local image sampling and source links for company palettes. Computed swatch/contrast colors are document data; product controls still use semantic tokens.
- Before changing JSON workflows, read `docs/json-workspace.md`. Preserve exact numeric tokens, local worker execution, bounded output/patch expansion, explicit previews and source/context-scoped results. Query/schema operations must not fetch references or execute pasted JavaScript.
- Before changing the PDF merger or the PDF splitter, read `docs/pdf-merger.md` and `docs/pdf-splitter.md`; the splitter writes each part with the merger's engine, so a change to one is a change to both. Only files named `mupdf-*.ts` (`lib/pdf-merger/mupdf-engine.ts`, `lib/pdf-reader/mupdf-read.ts`, `lib/pdf-splitter/mupdf-split.ts`) may import `mupdf`, and only its types; they are handed the engine or opened files, so the same code runs in the worker and in Node. The reader (`components/pdf-reader/`, `docs/pdf-reader.md`) is shared by every PDF tool: it draws pages, text and search through the one worker and never opens a file a second time. Pages are copied as whole objects after being made to stand alone, never with `graftPage`, which drops links, notes and fields. Check results with other software (pdf.js, pdf-lib), never with the engine alone, and keep the worker's message handler ahead of the engine import. Files are written with `garbage: 2` after `shareDuplicates` has stored identical parts once; do not go back to `garbage: 4`, which compares every object with every other and takes minutes on a long tagged file. Never call `resolve()` on an engine object: a stream that is held that way is written without its data.
- Before changing the PDF compressor, read `docs/pdf-compressor.md`. It changes a file in place and never turns a page into a picture. A picture is only swapped for a smaller one that has been read back out of the file and checked (pixel for pixel when nothing may be lost); pictures it is not sure of are left as they are; a JPEG is not saved twice at the same size. Level numbers are set by looking at results as well as by measuring: mean SSIM alone lets skies turn into bands. Only lossless JBIG2 is written (`lib/pdf-compressor/jbig2.ts`); do not add the kind that shares shapes between letters. Pictures are encoded on helper workers (`codec.worker.ts`, started by the page one after another and joined to the PDF worker by a port each); everything must still work with none, which is what a device with two cores gets. After changing what is done to pictures or streams, run `npm run pdf:benchmark` on the files listed in the docs and update the published table: it is where the engine's faults with real files were found.
- Before changing the PDF editor, read `docs/pdf-editor.md`. The document in the worker is the truth: every change is one step (`inStep`) and the page is drawn again from the file, so never keep a second model of the document on the page. A change is undone by making the working copy anew from the file as it came and the steps still in force (`madeAgain`); never call the engine's `undo()` or `redo()`, which leave it pointing at fonts and pictures that are gone, and check with `danglingRefs` in any test that undoes something. Changes to a signed file are written after it from such a fresh copy (`lib/pdf-editor/mupdf-signed.ts`), never by saving the working copy with `incremental`. Only the `mupdf-*.ts` files of `lib/pdf-editor/` touch the engine. A form's fields are the file's own (`lib/pdf-editor/forms.ts`): the engine writes their looks, except a list's, which it leaves blank and we draw; a file's scripts are read as text at most and never run. Never save the working copy with `garbage` (later steps name comments and fields by their numbers) and never keep a page object across a change. What is added is a Stamp annotation with our own appearance, set last with no `update()` after it, and is drawn into the page on download unless "Keep editable" is on. Everything read from a file or sent by the page goes through `readObject`. Comments (`lib/pdf-editor/comments.ts`, `mupdf-comments.ts`) are the PDF's own kinds of note, given their look by the engine; only the kinds the editor makes are ever given a new look, and annotations are taken off a page one at a time from a fresh list. Say only what a tool does: "Cover" hides and never removes. There is one PDF editor in the list of tools. A page that opens it for one job (the annotator, Sign PDF, Fill PDF form, Crop PDF, Add page numbers, Watermark PDF; later redaction) is a door: a catalogue entry with `partOf`, with its own address, title, help and article, shown focused on that job's tools with the rest one press away, and never a second card, sidebar count or app shortcut. A signature made here is a mark on the page and must never be described as a certificate or as proof of who signed; it is remembered on the device only when the switch is turned on, which starts off every time. A window opened from the editor is rendered inside the reader's own tree (a toolbar or panel slot), never beside it, or screen readers cannot reach it. The words a file already has are changed in `lib/pdf-editor/mupdf-text.ts`: the old letters are taken out of the page's content and the new ones written with the very font object the line was written with, by the numbers that font knows its letters by (learnt from a second copy of the file that is only read); never copy or re-embed a file's font, never take a shape that stands for several letters for its first, and keep the reading-back after every change, which refuses a change that would touch another line. Never run a page's content on the working copy outside an operation: the engine mends a faulty tagged file as it reads, and outside one it leaves a file that cannot be written (`read` opens its own). Lines that belong together are changed as a paragraph (`lib/pdf-editor/paragraphs.ts`): which lines those are is judged by their look and can be wrong, so the switch that turns it off stays; only the lines from the first one a change touches are written anew; a paragraph never grows over other text; how far apart words stand is measured from the paragraph and not assumed; links are taken along with their words by writing their place into the file ourselves (the engine's `setBounds` writes it upside down); and the field names the words it joined across line ends. A picture the page already has is changed by writing again the one instruction that draws it (`lib/pdf-editor/page-pictures.ts`, `mupdf-pictures.ts`): never decode or save its data again, never touch another instruction, keep the reading-back (other pictures and the text as they were), and say that cutting to a part hides and does not remove. Find and replace (`lib/pdf-editor/find.ts`) changes each place as a line or a paragraph is changed by hand, never by another way of writing; replacing everywhere is one step, and what cannot be changed is left out and said, never forced. A link (`lib/pdf-editor/links.ts`, `mupdf-links.ts`) is only ever given an address of the kinds `http`, `https`, `mailto` and `tel`, checked on the page and again in the worker; where it leads is never asked of the network, and the page says that it is not checked. A font of one's own (`lib/pdf-editor/own-font.ts`) is read on the device, goes by a key made from its bytes, and is never embedded when its maker restricts it; one font is taken out of a collection as a file of its own, and no bold or italic is made from it. Taking things out for good (`lib/pdf-editor/redact.ts`, `mupdf-redact.ts`) is two things that must never be said as one: a mark, which takes nothing out, and applying, which removes the letters, the pixels and the drawings under every mark and only then draws a black box; keep the reading-back that refuses a change when a letter can still be read under a mark, the count of marks under which something is still drawn, and the warning at the download for marks that wait; before the engine applies redactions for any purpose, give every Redact annotation that is not meant another kind for the call and its own again after it (the engine applies all of a page's at once); never write what was taken out after a signed file. Nothing of a file is kept on the device unless a switch is turned on: a draft (`lib/pdf-editor/draft.ts`, `draft-store.ts`) is the file as it came and the list of steps, kept in IndexedDB as bytes, read back through the same checks as a change from the page, and listed on the privacy page with everything else the editor can keep. The list of pages is changed in `lib/pdf-editor/mupdf-pages.ts` from a plan worked out in `pages.ts`: a page that moves is the same object in another place, never a copy, and never through the engine's `rearrangePages`, which drops tags, attachments, page numbers and the form's fields; a page that is taken out is emptied after what led to it is taken away, so that nothing of it stays in the file; a copy gets content of its own; the file's own page numbers are read before a change and written after it; another PDF whose pages are added is made ready once by the merging engine (`prepareInsert`) and kept as that, since a step must be able to be made again at once and without a password. Cropping (`reshape`) writes the box of what is shown by hand, from what is cut off the page as it is shown; it hides and never removes, and every place that names it says so. What is put on many pages at once (`lib/pdf-editor/repeated.ts`: page numbers, headers, Bates numbers, watermarks) is one ordinary added thing on each page, all in one step; do not give it a way of its own into the file, and say that a watermark does not protect a file. The file as a whole (`lib/pdf-editor/document.ts`, `mupdf-document.ts`: bookmarks, details, its own page numbers) is a kind of step that touches no page; bookmarks are written anew as a whole list, and a change to the details takes the file's second description (XMP) out so that the two cannot disagree. Never ask anything of an engine object that may be missing: `get` on it fails. Creating fields (`lib/pdf-editor/form-fields.ts`, `mupdf-form-fields.ts`) writes the PDF's own AcroForm as replayable steps, never a second page model; gathered field moves join `editor.onFlush` before another change, undo or download; new checkboxes and radio choices need their own Off/on appearances, and a radio parent's `Opt` labels must stay in the same order as its `Kids` when a widget is removed. New dates write only the fixed ISO `AFDate_FormatEx` format action; it is read as text and never run here. A signature place is empty and proves nothing; a filled certificate field cannot be changed here. Fields suggested from what a page draws (`lib/pdf-editor/form-suggest.ts`, `mupdf-form-suggest.ts`) are judged by look and only shown, to be taken or dismissed, never added unasked; suggesting changes nothing, and what is taken is one step made as a field added by hand; read a page's drawings with the engine's structured text (`vectors`), never with a device of our own. Recognising scans (`lib/pdf-editor/ocr.ts`, `mupdf-ocr.ts`) runs Tesseract on the device, loaded only when a run starts from the site's own `/ocr/<version>/` files (`app/ocr/[version]/[file]/route.ts`; never a CDN, never Tesseract's own store) and kept by the service worker once used; the words are laid unseen with the font that draws nothing, each stretched to its width, after the page's own content wrapped in `q … Q`, and the step holds the words, never the picture, so it is made again without Tesseract; a page that has text is left unless asked, the panel says how sure the reading was, Stop never waits on Tesseract, and the download reads every laid word back. When a Tesseract package changes, change `OCR_VERSION`. Languages are listed in `OCR_LANGUAGES` with the size of each file; right-to-left words are written in drawn order (`inDrawnOrder`) and words of scripts written together get no space (`spaced`): read a new script back with pdf.js, `pdftotext` and MuPDF before offering it. Tesseract reads with `OCR_PARAMETERS` (automatic page segmentation) everywhere it runs. The editor's keys are listed once, in `lib/pdf-editor/shortcuts.ts`, which the sheet (`?`) and the help are made from; its test holds the list to the code, so change both together. Untouched pages are checked at download by drawing the file as written, never the copy it was written from. Signing with a certificate (`lib/pdf-editor/certificate.ts`, `certify.ts`, `sign-bytes.ts`, `signatures.ts`, `mupdf-certify.ts`) happens at download, after everything else, as an update after the written file: the certificate file and its password are never stored, put in a draft or sent anywhere but the worker; the signature is read back before the file is handed over and never handed over when it does not hold; say that trust in a certificate is the reading program's to judge, never that a signature proves who signed; check results with OpenSSL and `pdfsig`, not with the code that made them. The signatures a file carries (`lib/pdf-editor/mupdf-signatures.ts`, `signature-report.ts`, `verdictOf`) are read from the file as it was opened, never from the working copy; what changed after a signature is found by opening the file up to where its ranges end beside the file as it is; nothing about a certificate is asked of the network and KeepSimp keeps no list of trusted issuers of its own: trust is judged only against certificates the person adds (`lib/pdf-editor/trust.ts`), each link of the chain checked by its signature, its dates and its right to issue, never by name alone, and kept on the device only while its switch is on; a signature that holds is never described as proof of who signed. Keep the sample's date inside its certificate's dates. Certificate files are opened by `pkcs12.ts` (WebCrypto, and our own decrypt-only 3DES and RC2 in `legacy-ciphers.ts`): node-forge is a test tool only, as its advisory fails the production audit. After changing how text is written or how OCR reads, run `npm run pdf:editor-benchmark` on the benchmark files and update the tables in the doc. The editor ships in phases (the list is in the doc); each is tested, pushed to `main` and checked live before the next.
- Before changing the audio workspace, read `docs/audio-workspace.md`. There is one audio tool, the Audio editor; the converter, the extractor and every later job are doors into it (`partOf`), never cards of their own. Only `lib/audio/mediabunny-audio.ts` touches Mediabunny, and it is handed the library. Every choice made for the person is worked out in `planFor` (`lib/audio/settings.ts`) and shown as a sentence. Sound is streamed, never held whole as samples. Keep files gapless: read an MP3's LAME header (`mp3Gapless`), write it into every MP3 (`lameTagged`), and write an edit list into every AAC file from the priming measured in this browser (`aacPriming`, `withEditList`); never assume a priming. Give bitrates as `new Quality({ bitrate })`, never `new Quality(number)`. Lossless integer samples are made by `asIntegers` from the decoder's floats, with no `sampleFormat` for them, so FLAC from FLAC is bit for bit. Every result is decoded again and checked (`checkResult`) before it is offered. A worker that stops a job says `retired` and is replaced, since a cancelled conversion can wait for ever on an encoder's worker. Downloads use an untyped link to the bytes; the page plays from a typed one. Check results with FFmpeg and FFprobe, not with Mediabunny alone. Edits are steps kept per file (`lib/audio/edits.ts`), in the times the person saw, and applied to the source while streaming (`shaped`); the file itself is never changed, an edited sound is always encoded again, every cut fades over `JOIN_FADE`, and a change of several steps is undone as one. The editor's keys are listed once in `lib/audio/shortcuts.ts`, which the help is made from. Its preview follows the edits on a timer, never on animation frames. Loudness is measured by `LoudnessMeter` (`lib/audio/loudness.ts`, BS.1770-5 with true peak) and checked against FFmpeg's `ebur128`; never against itself alone. A file is measured as it will be written, through the same conversion into a `NullTarget`, before its gain is chosen. The limiter (`lib/audio/limiter.ts`) is late by its look-ahead: keep every frame (let it out when the expected count is reached, write again when a decoder stops short), and never let a result go over its ceiling unsaid. Name a loudness target only with a published source. True peak uses the 24-tap Kaiser interpolator; a shorter one under-reads bright sound and lets the limiter pass its ceiling, so check any change to it against FFmpeg and a finer reference on bright, limited material. The equaliser and compressor (`lib/audio/sound.ts`) run on every pass, the measuring one too; silence trimming is made of ordinary steps. A split part is the file written with one more keep step, never a separate cutting path; a join passes each file through the same pass with `deliver` and one `Joiner`, limiter and encoder over all of them. Markers are kept in source time. Chapters are written by `lib/audio/chapters.ts` (ID3 CHAP/CTOC, Nero `chpl`) and checked with FFprobe; say that Apple's apps read another kind. Speed, pitch and channels run in `Changer` in every pass and must give exactly `framesAfter` frames; reversing goes through the joining engine's blob store, never by holding the decoded file in memory. Karaoke is never called a vocal remover. Repair (`lib/audio/repair.ts`) runs in `SoundShaper` and gives back exactly the frames it is given; RNNoise is loaded by the worker from the site's own `/rnnoise/<version>/` file only when asked and kept by the service worker once used (never bundled, never a CDN); say that it is made for voices, check it with the real model on speech, and never send anything about the sound anywhere. An MP3 decoder's delay is measured in each browser (`mp3DecoderDelay`), never assumed. Tags (`lib/audio/tags.ts`) are changed in place when the sound is copied into the same kind of file (`retag.ts` and a writer for each kind): write only what a change names, keep every other byte (sound, frames, items, blocks, chunks), refuse what a writer cannot be sure of (it then goes through the Mediabunny copy with `withChange`), and check results with FFprobe, ExifTool and FFmpeg's hash of the sound's packets. The recorder (`lib/audio/record.ts`, `components/audio/recorder.tsx`, `public/worklets/capture.js`) takes the microphone raw (the browser's call filters only when asked), keeps a take as blobs a second at a time and never whole, fades at every pause, and keeps a draft only while its switch is on, which starts off every time; the microphone is asked for only when Record is pressed.
- The site installs as an app and works offline; read `docs/pwa.md` before changing `app/manifest.ts`, `app/sw.js/route.ts`, `lib/pwa.ts`, `lib/offline.ts` or `service-worker/`. `next build` writes `/sw.js` through a static route; do not move that to a step after the build, because the host does not publish files added to `out/` later. The files in `service-worker/` stay plain JavaScript without imports, since their text is copied into the worker. Keep large media such as videos out of the offline copy through `service-worker/rules.js`, register the worker only from the workspace, and cover offline behaviour in `e2e/offline.spec.ts` with the server really stopped.
- Before delivery, run `npm run check`, `npm run test:e2e`, and inspect desktop/mobile UI. Run `npm run build` before standalone browser tests. CI runs all five browser/device profiles. Keep generated reports out of Git.
- Adding new shadcn components can restore default styles. Review their geometry and rerun design/browser checks before using them. A window (`components/ui/dialog.tsx`) or a sheet must never fade in: Safari on a phone cannot scroll by touch anything inside an element whose opacity was animated when it appeared. Let it grow or slide in and let the backdrop fade. No browser in the test suite shows this fault; it was found in the iOS simulator (`xcrun simctl`), which is the place to check anything that only a real phone's touch scrolling can show. Registry-internal geometry in `components/ui` is exempt from the product style scanner; it still requires review against the reference.

Research statements in the design reference must retain source links and distinguish Airbnb's public principles from KeepSimp's own numerical decisions. Phase one is a tested foundation. The marketing phase adds four working tools; the remaining catalogue entries must stay marked as coming soon.
